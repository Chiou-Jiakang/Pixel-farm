## 1. 產品願景與定位

Pixel Farm 是一款低門檻、以 4 × 4 格子農田為核心的單人農場經營網頁遊戲。玩家可透過「取得種子 → 種植 → 等待成熟 → 收成 → 販售 → 再投資」形成可持續的遊戲循環。現階段先完成「選擇作物 → 種植 → 成長 → 收成」的前端迴圈，後續導入經濟與存檔機制。

除了可玩性，本專案也作為漸進式全端工程實作：狀態管理、時間處理、物件資料模型、前後端分層、REST API、SQLite 交易與 Git 版本發布。

## 2. 目標使用者與情境

- 主要使用者：希望在瀏覽器進行短時間、操作直覺的單人農場遊戲玩家。
- 使用情境：開啟網頁、選種、播種、等待與收成，未來可累積資產擴大經營。
- v1.0.0 預設運作型態：本機單人 Web App；不承諾雲端同步與多人遊戲。

## 5. 關鍵遊戲規則

- **農田**：固定 4 × 4，共 16 格；每格最多同時種植一株作物。
- **作物**：v0.2.0 胡蘿蔔 10 秒、馬鈴薯 18 秒、番茄 30 秒，皆為暫定測試數值。
- **狀態**：空地（empty）／種子（seed）／幼苗（sprout）／成長中（growing）／成熟（mature）。
- **成長分段**：以成熟總時間比例劃分：0–25% 種子、25–50% 幼苗、50–100% 成長中、到期成熟。
- **收成**：成熟時點擊收成，格子恢復空地，收成數與對應作物分類數各加一。v0.2.0 尚無背包物品。
- **重設**：清空目前瀏覽器頁面內的農田狀態及統計；非資料庫操作。
- **時間信任模型**：v0.2.0 採 `Date.now()`；v0.4.0 預計將播種時間與合法性判斷交由後端。

## 6. 非功能需求（NFR）

| 編號 | 需求 | 目標／檢查方式 |
| --- | --- | --- |
| NFR-01 | 可用性 | 主要操作可透過點擊完成，附狀態提示 |
| NFR-02 | 可維護性 | UI、遊戲規則、API、資料存取在後端導入後分層 |
| NFR-03 | 一致性 | 後端交易以原子方式更新金幣與庫存 |
| NFR-04 | 持久性 | v0.4.0 起重啟後仍能載入有效存檔 |
| NFR-05 | 測試性 | 關鍵狀態與經濟規則能以可重現測試驗證 |
| NFR-06 | 文件化 | 每個版本更新 README、CHANGELOG、DEVLOG、TESTING、Release Notes |

以上 NFR 多數為 v1.0.0 目標，**不是 v0.2.0 已通過的測試結論**。

## 7. 後續建議資料模型（待設計審查）

- `game_saves`：存檔與金幣。
- `farm_plots`：格子、作物 ID、播種時間。
- `inventory`：種子與收成物持有量。
- `crop_types`：作物品種、價格與成熟時間（或以固定資料常數管理）。
- `transactions`：經濟交易紀錄。

正式 Schema、API 契約與交易邊界留待 v0.4.0 確認，本文不假稱已經建置。

## 8. 版本通過與變更管理

每一版的交付順序為功能實作 → 人工／自動測試 → 文件更新 → Git Commit／Push → Tag／Release。未驗收的功能須保持「待完成」狀態。若新增功能超出既定版本範圍，應先更新本文件與 `ROADMAP.md`。
